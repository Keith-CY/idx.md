# OpenClaw Skill Reference

## Product summary

OpenClaw is a self-hosted gateway that connects messaging apps (WhatsApp, Telegram, Discord, iMessage, Signal, and more) to AI agents. A single Gateway process runs on your machine or server and routes inbound messages to agents, manages sessions, handles tool execution, and streams responses back to channels. Key files: `~/.openclaw/openclaw.json` (config), `~/.openclaw/workspace/` (agent workspace with AGENTS.md, SOUL.md, TOOLS.md), `~/.openclaw/agents/<agentId>/sessions/` (session transcripts). Primary CLI: `openclaw` with subcommands for setup, configuration, channels, agents, models, and gateway control. See https://docs.openclaw.ai for comprehensive documentation.

## When to use

Use this skill when:
- **Setting up OpenClaw**: initial install, onboarding, workspace initialization
- **Configuring channels**: adding WhatsApp, Telegram, Discord, Slack, Signal, iMessage, or other messaging platforms
- **Managing agents**: creating multi-agent setups, routing messages to different agents, isolating workspaces
- **Configuring models**: selecting primary/fallback models, managing provider auth, setting up model failover
- **Creating or managing skills**: writing SKILL.md files, installing from ClawHub, gating skills by environment
- **Operating the gateway**: starting/stopping, health checks, logs, troubleshooting
- **Securing access**: setting DM policies, allowlists, pairing flows, group mention gating
- **Automating workflows**: setting up cron jobs, hooks, webhooks, heartbeat checks
- **Multi-agent routing**: binding channels to specific agents, isolating sessions and workspaces

### Config file structure

Config lives at `~/.openclaw/openclaw.json` (JSON5 format). Minimal config:

```json5
{
  agents: { defaults: { workspace: "~/.openclaw/workspace" } },
  channels: { whatsapp: { allowFrom: ["+15555550123"] } },
}
```

Key sections:
- `agents.defaults` — workspace, model, sandbox, heartbeat, session defaults
- `agents.list` — multi-agent definitions (id, workspace, agentDir, model, tools, sandbox)
- `channels.<provider>` — channel config (tokens, DM policy, allowlists, group rules)
- `models.providers` — custom model provider endpoints
- `bindings` — route inbound messages to agents by channel/account/peer
- `tools` — tool policy (allow/deny lists, exec approvals, elevated access)
- `skills.entries` — skill gating and env injection
- `gateway` — port, auth, TLS, tailscale, reload mode
- `session` — DM scope, thread bindings, reset behavior
- `cron`, `hooks`, `automation` — scheduled jobs, webhooks, automation

### Workspace files (agent context)

Inside `~/.openclaw/workspace/` (or per-agent workspace):

| File | Purpose |
|------|---------|
| `AGENTS.md` | Operating instructions, memory, task guidelines |
| `SOUL.md` | Persona, boundaries, tone, values |
| `TOOLS.md` | User-maintained notes (camera names, SSH details, preferences) |
| `IDENTITY.md` | Agent name, emoji, vibe |
| `USER.md` | User profile, preferred address |
| `BOOTSTRAP.md` | One-time first-run ritual (auto-deleted after completion) |
| `MEMORY.md` | Long-term memory (optional) |
| `memory/*.md` | Dated session summaries (auto-generated by hooks) |
| `skills/` | Workspace-specific skills (override bundled/managed) |

### Model refs

Use `provider/model` format:
- `anthropic/claude-opus-4-6`
- `openai/gpt-5.2`
- `openrouter/moonshotai/kimi-k2`

Supported providers: Anthropic, OpenAI, OpenRouter, Vercel AI Gateway, Cloudflare AI Gateway, Mistral, Moonshot, Synthetic, OpenCode, Z.AI, GLM, MiniMax, Venice, Bedrock, Qianfan, and more.

### Channel setup patterns

**WhatsApp**: `openclaw channels login --channel whatsapp --account default`

**Telegram**: `openclaw channels add --channel telegram --account default --token $TELEGRAM_BOT_TOKEN`

**Discord**: `openclaw channels add --channel discord --account default --token $DISCORD_BOT_TOKEN`

**Slack**: `openclaw channels add --channel slack --account default --token $SLACK_BOT_TOKEN`

All channels share DM policy pattern:
```json5
{
  channels: {
    telegram: {
      enabled: true,
      dmPolicy: "pairing",  // pairing | allowlist | open | disabled
      allowFrom: ["tg:123"],
    },
  },
}
```

## Decision guidance

### When to use X vs Y

| Decision | Use X when | Use Y when |
|----------|-----------|-----------|
| **Single vs multi-agent** | One agent, one workspace, one personality | Multiple agents, different workspaces, different people or roles |
| **DM policy** | `pairing` | Unknown senders get one-time code to approve | `allowlist` | Only known senders can message |
| **DM policy** | `open` | Allow all DMs (requires `allowFrom: ["*"]`) | `disabled` | Ignore all DMs |
| **Session scope** | `per-peer` | Each sender gets separate session | `per-channel-peer` | Sender + channel combo gets session (recommended multi-user) |
| **Sandbox mode** | `off` | No isolation, full host access | `non-main` | Sandbox non-main sessions only |
| **Sandbox mode** | `all` | Sandbox all sessions | `off` | No sandboxing |
| **Sandbox scope** | `session` | One container per session (resource-heavy) | `agent` | One container per agent (shared across sessions) |
| **Sandbox scope** | `shared` | One container for all agents (least isolation) | `agent` | One per agent (better isolation) |
| **Config reload** | `hybrid` | Auto-apply safe changes, auto-restart critical ones | `hot` | Only hot-apply, warn if restart needed |
| **Config reload** | `restart` | Restart on any change | `off` | Manual restart only |
| **Skill location** | Workspace `skills/` | Agent-specific skill (override bundled) | `~/.openclaw/skills` | Shared across all agents |
| **Tool policy** | `allow` list | Whitelist specific tools | `deny` list | Blacklist specific tools |
| **Group mention** | `requireMention: true` | Require @mention in groups | `requireMention: false` | Respond to all group messages |

## Workflow

### 1. Initial setup

1. Install: `npm install -g openclaw@latest`
2. Run onboarding: `openclaw onboard --install-daemon`
3. Choose gateway mode (local or remote)
4. Select model provider and authenticate
5. Add channels (WhatsApp, Telegram, etc.)
6. Verify: `openclaw status --deep`

### 2. Configure workspace

1. Edit `~/.openclaw/workspace/AGENTS.md` with operating instructions
2. Edit `~/.openclaw/workspace/SOUL.md` with persona and boundaries
3. Edit `~/.openclaw/workspace/TOOLS.md` with environment-specific notes
4. Create `~/.openclaw/workspace/skills/` for custom skills
5. Verify workspace: `openclaw agent --message "test"`

### 3. Add a channel

1. Get credentials (bot token, API key, etc.)
2. Run: `openclaw channels add --channel <name> --account <id> --token $TOKEN`
3. For WhatsApp: `openclaw channels login --channel whatsapp --account default`
4. Verify: `openclaw channels status --probe`
5. Set DM policy in config: `channels.<provider>.dmPolicy`

### 4. Set up multi-agent routing

1. Create agent workspaces: `openclaw agents add work` and `openclaw agents add home`
2. Create channel accounts: `openclaw channels login --channel whatsapp --account work`
3. Add bindings in config:
   ```json5
   {
     bindings: [
       { agentId: "work", match: { channel: "whatsapp", accountId: "work" } },
       { agentId: "home", match: { channel: "whatsapp", accountId: "personal" } },
     ],
   }
   ```
4. Verify: `openclaw agents list --bindings`

### 5. Create a custom skill

1. Create directory: `mkdir -p ~/.openclaw/workspace/skills/my-skill`
2. Write `SKILL.md` with frontmatter and instructions
3. Refresh: restart gateway or wait for watcher
4. Test: `openclaw skills list` and `openclaw agent --message "use my skill"`

### 6. Troubleshoot

1. Check logs: `openclaw logs --follow`
2. Run doctor: `openclaw doctor` (auto-fixes safe issues)
3. Probe gateway: `openclaw gateway probe`
4. Validate config: `openclaw config validate`
5. Check channel health: `openclaw channels status --probe`

## Common gotchas

- **Config validation is strict**: Unknown keys or malformed types cause the gateway to refuse to start. Run `openclaw doctor --fix` to repair.
- **Workspace is not a sandbox by default**: Relative paths resolve inside the workspace, but absolute paths can reach elsewhere on the host. Enable `agents.defaults.sandbox` for isolation.
- **Model refs must use `provider/model` format**: `anthropic/claude-opus-4-6` not just `claude-opus-4-6`. Lowercase is normalized.
- **Skills are loaded at session start**: Changes to `SKILL.md` or skill gating take effect on the next new session, not mid-session.
- **Per-agent auth is isolated**: Each agent reads from its own `~/.openclaw/agents/<agentId>/agent/auth-profiles.json`. Don't reuse `agentDir` across agents.
- **DM policy is global per channel**: You can't set different DM policies per agent on the same channel account. Use bindings to route to different agents instead.
- **Mention patterns are regex-safe**: Use `mentionPatterns: ["@openclaw", "openclaw"]` for text matching; native @-mentions are handled separately.
- **Session reset is destructive**: `--reset-scope full` deletes workspace files. Use `config+creds+sessions` to keep workspace.
- **Sandboxing requires Docker**: `agents.defaults.sandbox.mode` requires Docker to be installed and running. Build the image first: `scripts/sandbox-setup.sh`.
- **ClawHub skills are public**: All skills published to ClawHub are visible to everyone. Don't publish secrets or private code.
- **Tool policy is per-agent**: `agents.list[].tools` overrides global `tools.*` for that agent. `tools.elevated` is always global and sender-based.
- **Config hot reload has limits**: `gateway.*` (port, auth, TLS) and `plugins` require a restart. Most other changes hot-apply in `hybrid` mode.
- **Secrets in config**: Use SecretRef objects (`{ source: "env", provider: "default", id: "VAR_NAME" }`) instead of plaintext. Never commit plaintext keys.

## Verification checklist

Before submitting work or deploying:

- [ ] Config validates: `openclaw config validate`
- [ ] Gateway starts: `openclaw gateway start` (or `openclaw gateway --port 18789`)
- [ ] Gateway is healthy: `openclaw health` or `openclaw status --deep`
- [ ] Channels are connected: `openclaw channels status --probe`
- [ ] Agents are listed: `openclaw agents list --bindings`
- [ ] Models are available: `openclaw models status`
- [ ] Skills are eligible: `openclaw skills list --eligible`
- [ ] Workspace files exist: `ls ~/.openclaw/workspace/{AGENTS,SOUL,TOOLS,IDENTITY,USER}.md`
- [ ] One agent turn works: `openclaw agent --message "hello"`
- [ ] Logs show no errors: `openclaw logs --limit 50`
- [ ] Multi-agent bindings are correct: `openclaw agents list --bindings` matches config
- [ ] DM policy is set: `channels.<provider>.dmPolicy` is not `disabled`
- [ ] Sandbox (if enabled) is working: `openclaw sandbox list` shows containers
- [ ] Secrets are not plaintext in config: grep for API keys in `~/.openclaw/openclaw.json`
